# Migration guide: 1.x to 2.0

This guide covers version 2.0.0-preview.1.

## Validation attributes

**Before:** `ValidationAttribute` annotations on properties and parameters were ignored, except `[Required]` on an option, which made the option mandatory.

**After:** CmdStarter applies DataAnnotations validation attributes to options and arguments created from properties and parameters. Review any existing annotations: values that previously passed without validation may now produce parse errors. An absent optional value, including one supplied by a default, is not validated. Use `ErrorMessage` to replace DataAnnotations' default English message.

```csharp
[Range(1, 65535, ErrorMessage = "Port must be between 1 and 65535.")]
public int Port { get; set; } = 8080;
```

## Public namespaces

**Before:** Library types used `com.cyberinternauts.csharp.CmdStarter.Lib` and its child namespaces. Other projects used `com.cyberinternauts.csharp.CmdStarter.<Project>`, while the SimpleInjector demo used `CmdStarter.Demo.SimpleInjector`.

**After:** Replace `com.cyberinternauts.csharp.CmdStarter.Lib` with `CyberInternauts.CmdStarter` and `com.cyberinternauts.csharp.CmdStarter` with `CyberInternauts.CmdStarter` throughout source code, namespace filters, and fully qualified class filters. Use `CyberInternauts.CmdStarter.Demo.SimpleInjector` for the demo namespace. The assembly remains `CmdStarter.Lib.dll` and the package remains `cints.CmdStarter`.

```csharp
using CyberInternauts.CmdStarter;
using CyberInternauts.CmdStarter.Attributes;
```

## Public constants

**Before:** Public constants used underscore-separated names.

**After:** Update references to the PascalCase names:

| Before | After |
| --- | --- |
| `Starter.EXCLUSION_SYMBOL` | `Starter.ExclusionSymbol` |
| `Starter.ANY_CHAR_SYMBOL` | `Starter.AnyCharSymbol` |
| `Starter.ANY_CHAR_SYMBOL_INCLUDE_DOTS` | `Starter.AnyCharSymbolIncludeDots` |
| `Starter.MULTI_ANY_CHAR_SYMBOL` | `Starter.MultiAnyCharSymbol` |
| `Starter.MULTI_ANY_CHAR_SYMBOL_INCLUDE_DOTS` | `Starter.MultiAnyCharSymbolIncludeDots` |
| `StarterCommand.OPTION_PREFIX` | `StarterCommand.OptionPrefix` |
| `StarterCommand.DESCRIPTION_JOINER` | `StarterCommand.DescriptionJoiner` |
| `AliasAttribute.DEFAULT_PREFIX` | `AliasAttribute.DefaultPrefix` |
| `IStarterCommand.EMPTY_EXECUTION` | `IStarterCommand.EmptyExecution` |

## `VisitCommands` is static for a starting node

**Before:** Call `starter.VisitCommands(rootCommand, action)` on a `Starter` instance.

**After:** Call the starting-node overload statically. The overload that visits from the root remains an instance method.

```csharp
Starter.VisitCommands(rootCommand, action);
starter.VisitCommands(action);
```

## `IServiceManager` is obsolete

**Before:** Pass a custom `IServiceManager` to `Starter.Start` to create command instances.

**After:** Set `ServiceProvider` or use `CmdStarterBuilder` for Microsoft.Extensions.DependencyInjection. For another container, discover command types, register them, and supply a factory:

```csharp
using CyberInternauts.CmdStarter;
using CyberInternauts.CmdStarter.Demo.SimpleInjector.Services;
using CyberInternauts.CmdStarter.Interfaces;
using SimpleInjector;

var starter = new Starter();
var container = new Container();
container.Register<IService, Service2>(Lifestyle.Singleton);
starter.FindCommandsTypes();
foreach (var commandType in starter.CommandsTypes)
{
    container.Register(commandType);
}
starter.SetFactory(type => (IStarterCommand)container.GetInstance(type));
int exitCode = await starter.Start(args);
```

`IServiceManager` and its `Start` overloads are planned for removal in 3.0.

## Unhandled exception output

**Before:** An unhandled command exception wrote its full stack trace by default.

**After:** CmdStarter writes only the exception message on one line and returns exit code `1`. Set `ShowExceptionDetails` to `true` to restore System.CommandLine's full exception output.

```csharp
var starter = new Starter { ShowExceptionDetails = true };
```

## .NET 10 is required

**Before:** CmdStarter 0.9 could be used with earlier .NET versions.

**After:** CmdStarter 2.0 targets .NET 10 only. Update the target framework of your application to `net10.0` and install the .NET 10 SDK.

## System.CommandLine 2.0.14 changes

**Before:** Code using the previous System.CommandLine API may have treated an option's name as the name without its prefix, included the name in `Aliases`, or used `IsHidden` and `IsRequired`.

**After:** CmdStarter 2.0 uses System.CommandLine 2.0.14. `Option.Name` includes the `--` prefix, `Aliases` contains aliases only, and the properties are named `Hidden` and `Required`. Help text is localized by System.CommandLine.

```csharp
var optionName = option.Name; // For example: "--output"
var hidden = option.Hidden;
var required = option.Required;
```

## Auto-completion callback type

**Before:** `AutoCompleteAttribute.Context` used the earlier completion callback type.

**After:** It is now `Func<CompletionContext, IEnumerable<CompletionItem>>`. Update callback parameters and return values to use `CompletionContext` and `CompletionItem`.

```csharp
using System.CommandLine.Completions;
using CyberInternauts.CmdStarter.Attributes;

Func<CompletionContext, IEnumerable<CompletionItem>> completions =
    new AutoCompleteAttribute("choice").Context;
```

## `StarterCommand` is no longer a System.CommandLine `Command`

**Before:** A `StarterCommand` instance was also the command node, and interface-only commands were wrapped in `GenericStarterCommand<T>`. Callers could use `UnderlyingCommand` to access the user's command instance.

**After:** `StarterCommand` implements `IStarterCommand` but does not derive from `Command`. Use `Starter.FindCommand<T>()` to obtain the System.CommandLine node and `Starter.FindCommandInstance<T>()` to obtain the description instance created while building the tree. This instance supplies command metadata and is never executed. For a node already in the tree, use `Starter.FindCommandInstance(Command)`. `UnderlyingCommand` and `GenericStarterCommand<T>` have been removed. `StarterCommand.GetInstance<T>()` returns `IStarterCommand`. `StarterCommand.GetFullCommandString()` still exists; for any command type, including classes that only implement `IStarterCommand`, use `Starter.GetFullCommandString<T>()`.

**Lonely command:** when a single command is rooted (`IsRootingLonelyCommand`), its subcommand node is now really hidden from help. In 1.x the code set it hidden, but attribute loading reset the flag, so it was listed under "Commands".

```csharp
Command? node = starter.FindCommand<MyCommand>();
MyCommand? instance = starter.FindCommandInstance<MyCommand>();
IStarterCommand? instanceForNode = node is null
    ? null
    : starter.FindCommandInstance(node);
```

## Command instances are created for each execution

**Before:** The command object used to build the tree was also used for every execution. Tests and callers read handler state from `FindCommandInstance<T>()` after `Start`.

**After:** CmdStarter creates a new execution instance for each run and releases it when the run ends. `FindCommandInstance<T>()` still returns the description instance. Subscribe to `CommandHandled` to observe the instance that ran the handler.

```csharp
IStarterCommand? executed = null;
starter.CommandHandled += (_, e) => executed = e.Instance;
int exitCode = await starter.Start(args);
```

## `StarterCommand` constructor description is used for help

**Before:** A description passed to `StarterCommand(string name, string? description)` was stored on the instance but did not appear in help.

**After:** When the command has no `[Description]` attribute, the constructor description is used for its command node (including the root node for a rooted lonely command). A `[Description]` attribute takes priority.

```csharp
public sealed class ListUsersCommand : StarterCommand
{
    public ListUsersCommand() : base("list-users", "List registered users") { }
}
```

## `CommandHandledEventArgs.Instance` is `object?`

**Before:** The `CommandHandledEventArgs.Instance` property was introduced in 2.0 with the class-based command instance type.

**After:** It is `object?` so it can also contain the method model's declaring class instance, or `null` when a static method ran. Cast it to the type your handler uses when needed.

## `SetFactory` and `SetDefaultFactory` are instance methods

**Before:** `Starter.SetFactory` and `Starter.SetDefaultFactory` changed a process-wide factory shared by every starter.

**After:** Configure only the `Starter` instance that should use the factory. A factory must return a fresh instance per call; instances returned by the factory remain owned by the factory.

```csharp
var starter = new Starter();
starter.SetFactory(type => (IStarterCommand)Activator.CreateInstance(type)!);
starter.SetDefaultFactory();
```

## Command disposal

**Before:** CmdStarter reused command instances and did not define a disposal boundary per invocation.

**After:** CmdStarter disposes execution instances it constructs through the parameterless constructor or `ActivatorUtilities`. It prefers `IAsyncDisposable` during execution, otherwise uses `IDisposable`. Microsoft DI scopes dispose their resolved command and scoped services. Custom factories and `IServiceManager` implementations own and dispose instances they return.

```csharp
public sealed class MyCommand : StarterCommand, IAsyncDisposable
{
    public ValueTask DisposeAsync() => ValueTask.CompletedTask;
}
```

## Microsoft.Extensions.DependencyInjection support

**Before:** Use a custom `IServiceManager` adapter to supply services. That API remains available and does not create scopes.

**After:** `CmdStarterBuilder` configures Microsoft DI, validates scopes and registrations by default, and creates an asynchronous scope for every command execution. Dispose the application to release singleton services.

```csharp
await using var app = new CmdStarterBuilder()
    .AddCommandsFromAssembly(typeof(MyCommand).Assembly)
    .ConfigureStarter(starter => starter.Namespaces = starter.Namespaces.Add("MyApp.Commands"))
    .Build();
app.Services.GetRequiredService<IClock>();
int exitCode = await app.RunAsync(args);
```

## Assemblies filter

**Before:** Command and global option discovery searched every assembly loaded in the AppDomain.

**After:** Set `Starter.Assemblies` to restrict discovery. An empty list preserves the all-loaded-assemblies behavior. `CmdStarterBuilder.AddCommandsFromAssembly` configures the same filter.

```csharp
starter.Assemblies = starter.Assemblies.Add(typeof(MyCommand).Assembly);
```

## Command discovery order is deterministic

**Before:** Reflection order determined the order of discovered commands and global options, and could affect which command received a child claimed by multiple `[Children]` attributes.

**After:** Commands and global options are sorted by their type's full name using ordinal ordering, which can change the order shown in help. When two commands claim the same `[Children]` child, the command whose full type name comes last in ordinal order receives it; previously, the result depended on reflection order.

## Configuration exceptions share `CmdStarterException`

**Before:** Configuration exceptions did not share a common CmdStarter base type.

**After:** Configuration exceptions derive from `CmdStarterException`. They are thrown while the command tree is built and can be caught through that common base type.

## Name conflicts and property option defaults

- **Name conflicts:** Two commands with the same name caused a System.CommandLine `ArgumentException` during `Start`; they now cause `InvalidAttributeException` during `InstantiateCommands`. Options on the same command that share a name or alias, including help and version options, are also rejected during instantiation.
- **Property option defaults:** The help now shows an option property's initial value as its default, except when it is `null`, an empty string or collection, the type's default value, or the option is `[Required]`.
- **Initialized Boolean options:** A `bool` property initialized to `true` now keeps that value when its option is omitted; previously it became `false`.

## `Starter` can be inherited

**Before:** `Starter` was sealed and could not be used as a base class.

**After:** `Starter` is no longer sealed. It can be inherited when an application needs to extend its behavior.

## Parse errors return a non-zero exit code

**Before:** The behavior for parse errors was not documented consistently.

**After:** A parsing error is reported by System.CommandLine and the command returns a non-zero exit code. `Starter.Start` does not throw for parse errors; check the returned code.

```csharp
int exitCode = await starter.Start(args);
if (exitCode != 0)
{
    // The command line could not be parsed or execution failed.
}
```

## REPL input providers

**Before:** `IReplInputProvider.GetInput()` returned a string. A closed standard input was converted to an empty string, so the REPL could not distinguish end of input from an empty command.

**After:** Implement `ValueTask<string?> GetInputAsync(CancellationToken cancellationToken)`. Return `null` when input has ended. `ReplStarter.Launch` accepts an optional cancellation token and stops its loop automatically at end of input. Empty lines are ignored.

```csharp
public ValueTask<string?> GetInputAsync(CancellationToken cancellationToken) =>
    Console.In.ReadLineAsync(cancellationToken);
```

## REPL built-in commands

**Before:** The REPL had no built-in commands for leaving the loop or showing help.

**After:** `exit` and `quit` end the loop, and `help` shows root help. Use `help <command line>` to show help for a command. Set `ExitCommands` or `HelpCommands` to an empty list to disable that built-in behavior. These built-in words take priority over application commands with the same name.

## Command cancellation

**Before:** Class-based handler parameters were treated as command-line arguments, including `CancellationToken`.

**After:** A `CancellationToken` parameter in a class-based handler receives the invocation token and creates no argument. If a handler throws `OperationCanceledException` after cancellation was requested, the command returns exit code `130`. Pass a token to `Starter.Start` or `ReplStarter.Launch`; in a REPL, Ctrl+C during a command cancels that command.

```csharp
public Task<int> ExecuteAsync(CancellationToken cancellationToken) =>
    RunWorkAsync(cancellationToken);
```

## Starter registration in Microsoft DI

**Before:** `CmdStarterBuilder` did not register the created `Starter` in the service collection.

**After:** The built application's `Starter` is available from `app.Services`. In REPL mode, the same instance is available as `ReplStarter`; configure it with `UseRepl(inputProvider)` and start it with `RunReplAsync`.

```csharp
await using var app = new CmdStarterBuilder()
    .AddCommandsFromAssembly(typeof(MyCommand).Assembly)
    .Build();
Starter starter = app.Services.GetRequiredService<Starter>();
```

## Additions since the 2.0 preview

These additions do not break an existing application, except for the REPL change described below.

- REPL line editing: history, Tab completion, and the `ConsoleReplProvider.LineEditing` and `HistorySize` settings. Completions come from `ReplStarter.GetCompletions`. See [ADR 0020](../adr/0020-repl-line-editing.md) and [REPL](../guides/repl.md).
- Startup measurements: the `benchmarks/CmdStarter.Benchmarks` project measures discovery, tree building and execution. See [Performance](../advanced/performance.md).
- Per-execution console: `CommandConsole`, `Starter.DefaultConsole`, `Start(args, console)`, a `CommandConsole` handler parameter and `CommandContext.Console`. See [ADR 0021](../adr/0021-command-console.md) and [Command console](../guides/command-console.md).
- Command sequences: `;`, `&&` and `||`, with `Starter.StartSequence` and `Starter.SequenceOption`. See [ADR 0022](../adr/0022-command-sequences.md) and [Sequences and pipes](../guides/sequences-and-pipes.md).
- Text pipes: `|`, with `CommandSequenceStep.Pipeline`. See [ADR 0023](../adr/0023-text-pipes.md) and [Sequences and pipes](../guides/sequences-and-pipes.md).
- Remote REPL over a named pipe: `ReplPipeServer` and `ReplPipeClient`. See [ADR 0024](../adr/0024-remote-repl.md) and [Remote REPL](../guides/remote-repl.md).

**Behaviour change in the REPL:** in a REPL line, `;`, `&&`, `||` and `|` outside double quotes are now operators, so an argument that contains one of them must be quoted. A line with no operator runs as before.
